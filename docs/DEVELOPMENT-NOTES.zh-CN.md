# ThinkPad 700 参考盘 + Windows 3.2

已完成并实机验证的本地配置：

- 86Box 6.0 ARM64 本地构建（包含 ThinkPad 700/9552 机型适配）
- IBM 486SLC/25、16 MB 总内存（该机型支持的最大容量）
- ThinkPad 700 单色机型 Planar ID `F1EE`
- IBM ROM `39G9996` 的校验正确单色变体
- IBM PS/2 Reference Diskette 1.20，冷启动时优先从 A: 启动
- 720CC 硬盘系统副本，自动进入中文 Windows 3.2
- 640×480、4:3、White monitor 灰阶、最近邻缩放
- ARM64 动态重编译与轻量 SDL 软件贴图输出

显示前端固定模拟一块 640×480 LCD：720×400 的 POST/DOS 和 640×400 的参考盘
画面上下居中，Windows 的 640×480 画面使用完整面板。切换模式时不会再改变宿主
窗口大小，VGA 临时上报的 80×400/80×480 中间帧也不会被放大显示，因此各阶段的
左右边界保持一致。POST 内存数字整体向右保留一个半字符宽度，而且从计数开始到
中途检查点切换都锁定同一组边框和缩放参数，不会再次横向放大；最左侧数字不会被
面板边缘裁切，同时右下角 CP 码仍保持在屏内；磁盘开始引导以后，所有
640×400/720×400 文本画面使用左右各一列（窗口模式 8 像素）的 LCD 安全边距，所以
`Starting PC DOS...`、参考盘边框和 `C:\>` 不会再切入左侧边界。Windows 3.2 退出时
恢复的文本时序被规范回 720×400 九点阵，与进入 Windows 前一致，字体不会突然变宽。

## 启动

双击或在终端运行 `启动-ThinkPad-700-参考盘.sh`。启动器会先校验并初始化
ROM/NVRAM/硬盘工作副本（通常约 10–15 秒），然后以 4:3 全屏启动。等待期间再次
双击不会启动第二个实例。

冷启动会在左上角显示类似 Model 50/70 的递增内存数字（例如 `03328 KB OK`），右下角会同时显示跳动的 `CP: 52`、`CP: 62`、`CP: 66` 等 POST 检查码。`OK` 已在原始 IBM ROM 二进制和未加宿主叠加的启动画面中交叉确认，确实是原机 ROM 输出，因此予以保留。模拟器在第一个 700 POST 检查点打开客机的 80×25 文本显示，数字与检查码随后由 700 ROM 自身写入客机显存，不是宿主 SDL 画面叠加；参考盘切换视频模式后不会残留。随后直接进入参考盘
`Main Menu`，不再出现 `00160/00164/00169`、`12902`、`00201`、`08611`
或 `00191` 等错误。

进入 Windows 3.2：

1. 在主菜单选择 `1. Start operating system` 并按 `Enter`。
2. 提示重新启动时再按一次 `Enter`。
3. 机器会重新执行完整 POST，由参考盘把控制权交给硬盘，然后自动进入中文
   Windows 3.2。

参考软盘始终保持挂载，因此下一次冷启动仍会优先进入参考盘。原始
`720CC.rar` 不会被改写，模拟器只使用转换后的工作副本。

## 鼠标和全屏

- 点击模拟器画面：捕获鼠标。
- `Ctrl+End`：释放鼠标；独立 End 与数字键盘 End 均可使用，并会强制清除 SDL
  相对模式、窗口抓取和鼠标捕获（已用完整宿主按键事件实测）。
- 鼠标中键：备用释放方式。
- `Ctrl+Alt+Page Up`：在全屏与窗口模式之间切换（SDL 前端已补全该快捷键）。

要关闭模拟器：先用 `Ctrl+Alt+Page Up` 退出全屏，再点击窗口右上角的关闭按钮。

## POST/参考盘错误的本源修复

没有屏蔽错误字符串或跳过参考盘检测；以下项目均修复其设备或配置来源：

- `00160/00164/00169`、`00201`：改正 ThinkPad 700 的 `F1EE` Planar 标识、4 MB
  板载内存与扩展卡拓扑、16 MB 存在位、192 KB 保留区映射以及 NVRAM/EBDA
  配置的一致性。486SLC 的 24 位地址空间原先错误地把 256 KB 高位 BIOS 映射覆盖到
  `FC0000h`，导致 POST 少测 128 KB；现按 700 的 128 KB 高位 ROM 窗口只映射
  `FE0000h–FFFFFFh`，因此 16 MB 与参考盘记录的 `3B80h` 可用扩展内存一致。
- `12902`：实现 IBM 486SLC 的 16 KiB、四路组相联缓存标签以及 `CRLD` 命中/未命中
  状态，并在 DMA 总线接管时正确失效。Windows 性能快路径只在 ROM 写入正常的
  多区域 CRCR、缓存诊断结束后生效；POST 使用单独的 `00000080h` 诊断区域期间仍逐次
  模拟标签，因此不会因优化而误报缓存故障。二级 NVRAM 的 `04EAh` 失败锁存只在启动
  前作为维修后的复测初始化清零，随后由真实 POST 重新检测，未屏蔽错误判断。
- 系统板/VPD 检查：补齐 VPD 串行 EEPROM 的访问协议、机器序列字段和 CRC，使参考盘
  读到有效的系统板身份数据。
- `08611`：修复 8042 键盘控制器的命令参数提交顺序和 IRQ 时序，使 TrackPoint/PS/2
  指点设备能按真实初始化流程通过检测。
- `00191`：实现 PS/2 软驱控制器的电源关闭/状态回读行为，参考盘不再把软驱控制器
  判断为故障。
- ESDI/启动系统：实现 MCA ESDI 控制器所需的命令、几何参数和电源状态，并修正
  参考盘到硬盘的启动交接。
- `I9990303`：IBM 对该码的定义是“IML 未能从 System Partition 装入”。本机的系统
  分区实际位于 370 柱面 ESDI 镜像末尾固定的 `1800h` 扇区（3 MiB）。ROM 在进入
  `INT 19h` 前会从磁盘最后一个扇区向前搜索 99 个扇区，每次读取 3 个扇区，并要求
  找到以 `IML` 开头且 0x600 字节校验为零的主 IML 记录。此前 FAT12 系统文件虽然
  完整，但这段原始尾端记录全为零，所以 ROM 留下 `I9990303` 后才继续启动 DOS。
  启动器现在从原版参考盘读取校验正确的 `$BOOT.IML`，恢复到 ROM 搜索的最后 3 个
  扇区，并同时核对末尾系统区的 MBR、FAT12 BPB 和关键系统文件；没有屏蔽错误字符串。
  若系统区确实损坏，只恢复保留的最后 3 MiB，不触碰 Windows 分区。
- Windows 3.2 鼠标初始化：修复 8042 参数 `25h` 被后续 `A7h` 命令覆盖的竞态，先提交
  参数再延迟触发 IRQ12。

参考盘介质只在工作副本中补齐设备描述/IML 关联；原始压缩包和原始镜像保持不变。

## 流畅度

本机的 Rockchip GLX 驱动不可用，原先 OpenGL 路径会退回 8 线程 `llvmpipe`，单纯
缩放 640×480 画面也会占用约一个 CPU 核，鼠标移动和下拉列表重绘时尤其明显。该机型
现固定使用 SDL 软件贴图路径，并启用 ARM64 动态重编译；Windows 3.2 中连续移动鼠标
的实测模拟速度约为 82–97%，空闲/普通操作通常约为 85–100%。同时已关闭只用于开发
阶段的高频 I/O、CMOS、返回指令和软驱电机日志，正常空闲时日志不再持续增长。

## 实体 ThinkPad 700C 面板

一键启动器会使用本机现有的 ESP32/CH340 面板服务，不会直接抢占串口。86Box 采用
按鼠标归属切换的“解除耦合”模式：鼠标被 86Box 捕获时，亮度、对比度、音量和反色
只作用于客机；按 `Ctrl+End` 释放鼠标后，客机控制租约立即撤销，物理控制条恢复作用
于正常宿主系统；再次点击模拟器画面后恢复客机控制。退出模拟器也会自动交还控制权。

- 亮度滑块：只调整 86Box 客机纹理亮度，不重复写 DP-1 的整机亮度。
- 对比度滑块：只调整 86Box 客机纹理对比度，不修改桌面的既有 gamma/对比度。
- 三档音量开关：只控制 86Box 的静音、50%、100% 相对音量；不会跟着改桌面默认音频设备。
- 黑白反转开关：只反转 86Box 客机纹理；GNOME 的整机反色效果在模拟器活动期间暂停，避免双重反色。
- Num/Caps/Scroll、硬盘和软盘灯：86Box 导出来宾机状态，面板服务在本模拟器运行时优先采用这些状态；模拟器退出后自动回到宿主机状态。
- 电源灯：在 ThinkPad 700 模拟器运行期间点亮。

面板的原始串口协议、校准范围和既有系统配置保持不变；本次接入增加了来宾机状态桥接和控制隔离。鼠标被捕获时 `/run/thinkpad700c-leds/slider-status.json` 与 `switch-status.json` 中的 `host_controls_enabled` 为 `false`；释放后恢复为 `true`。来宾灯状态租约位于 `/run/user/1000/thinkpad700c-emulator/panel-status.json`，释放鼠标或退出模拟器时会撤销。

## ThinkPad 700C Windows x64 验证（2026-11-13）

700C 使用独立的 `ibmtp700c` 机型、BIOS/NVRAM 名称与工作介质。原版 `39G9996`
ROM 保持 F1EC，参考盘为 `r700c120` 1.20，包含 PF1EC/SF1EC 和 `$0009000.IML`。
原始固件、软盘和用户压缩包均保留，仅修改本地工作副本；这些文件不进入版本库。

- VPD CRC 根据实际序列字段计算，消除 POST 00187 和系统身份修复提示。
- 通过参考盘原有的恢复系统分区流程写入 700C 系统程序，按提示插入通用诊断盘，
  再运行自动配置。恢复阶段核对 Windows 分区散列，确认其内容未被改写。
- MCA ESDI 的 POS 仲裁级别 E 映射到固件配置的 PS/2 DMA 通道，修复自动配置
  重启时的 10482；READ BUFFER 等待 DMA 时也保留正确的扇区进度。
- 全零空错误日志初始化 FF 签名，修复日志页面 AX=0521h/AH=02 的程序错误。
  已有非空记录不会被这段初始化清除。
- 参考盘版本页显示 BIOS 39G9996、机型 F8/5E、Reference 1.20 和 `$0009000.IML`；
  身份页显示 `9552-30B-0000001`。错误日志实际显示 “The system error log is empty.”。
- 多次冷启动直接进入 700C 参考盘主菜单，无配置或身份错误提示；从
  **Start operating system** 完成完整 POST 后进入彩色 Windows 3.2，并正常退出。
  Windows 恢复其浅蓝底、黑字选中配色。
- 最终 Qt 软件渲染运行包已全屏启动，保持 4:3，禁用灰阶。700C 的 400 行文本
  默认居中显示在 480 行面板内；700 单色路径仍保留原有居中显示。
- Qt 和 SDL 目标构建通过；实际 DMA 仲裁函数的通道分配、屏蔽、重新分配与旧端口

### VGA256C 256 色驱动验证

通过 IBM `700C120` 1.20 安装盘的 VGA256C 安装程序和 Windows SETUP，安装
`WSPDSF.DRV`、`VDDSPD.386` 与 `V7VGA.3GR`。安装程序把 `VESA.COM` 加入
AUTOEXEC，在 Windows 之前加载，并将 `vesa` 加入 `localtsrs`。

原有通用 VGA 的显卡 POS 身份为 EFFD，IBM VESA TSR 因此无法识别显卡。700C 的
专用显卡设置窗口现返回 90FB，主板设置窗口仍返回 F1EC。显示设备使用 512 KiB
显存、2100h 模式寄存器、2108h 银行寄存器及索引寄存器；扩展模式使用紧凑的
chain-4 地址布局，避免 256 色像素被旧 VGA 地址变换打散而产生条纹。

已实测从参考盘菜单启动 Windows 3.2 标准模式，显示为 640×480、8 位扫描，显存
大小 524288 字节；在画笔中打开自行生成的 256 色测试位图并查看整幅图，截图采样
得到 245 个不同 RGB 颜色（Windows 调色板保留色会匹配部分输入颜色）。这一结果
与 8 位显存扫描状态交叉验证，排除了仍在 16 色模式下运行的情况。

700 单色机型用同一新构建再次冷启动，正常进入单色参考盘主菜单。
桌面快捷方式指向本地 700C 启动包，仍由 700C 参考盘优先启动，并默认全屏。

增强模式驱动行为、扩展视频加速及完整硬件诊断尚未验证。

### 键盘 LCD 调节与启动耗时复核

Qt 软件渲染和 SDL 前端增加 Ctrl+Shift+F5/F6 亮度减/增、F7/F8 对比度减/增、
F9 复位。只对客机 RGB 输出做数字变换，不加控件、滑条、数值或 OSD，不调用
宿主显示器的亮度接口；功能键按下和释放均被宿主消费。Windows Raw Input 路径
也会过滤对应功能键，避免调屏时同时触发客机功能。默认 100/100 直接走原图路径。

最终运行包经桌面快捷方式全屏启动，实际按五个组合键并保存渲染截图：灰色背景
由 RGB 170/170/170 调暗为 153/153/153，对比度减/增分别为 165/165/165 和
174/174/174。提高亮度回到默认、F9 复位后的整张 RGB 图像均与初始截图逐像素
相同；2160×1620 全屏尺寸和上下黑边不变，参考盘菜单未被组合键切换。

在固件端口 0680h 记录检查点转换时间，同一 16 MiB、25 MHz 配置的原构建和
修正构建均在约 38 秒完成 POST，其中 CP52 内存检查约 32 秒，CP67 到 CP68
小于计时器的毫秒分辨率。没有重现 CP67 固件卡死，未跳过或缩短原始内存自检。
另外确认 CPU 循环中遗留的全内存 IML 诊断扫描使用了 700 的签名，700C 下可能
长期找不到目标，现只在启用 CPU 诊断日志的构建中保留，正常构建不执行该扫描。

本次 Qt 与 SDL 构建成功；700C 参考盘错误日志为空，参考盘菜单交接到 Windows
3.2 后仍为 640×480、8 位扫描、512 KiB 显存；700 单色参考盘启动回归通过。
